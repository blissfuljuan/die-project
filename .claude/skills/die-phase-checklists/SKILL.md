# Phase checklists (brief v1.0, `docs/brief.md`)
Terms: Project Participant / Project Coordinator / Administrator; Project Workspace (one Owner, several Coordinators). Live status per slice: `docs/slice-tracker.md`. Slice IDs are stable; withdrawn IDs are never reused. Every slice integrates frontend + backend + persistence + security + infrastructure; mock-only success is not acceptance.

**P0 Foundation** — VS01 full-stack foundation (typed API client, status endpoint, connected/disconnected/retry UI, smoke tests) · VS02 database (Supabase profiles, Flyway baseline, separate app/migration credentials, restart persistence) · VS03 auth + sessions (shared server sessions, security-version checks, CSRF/origin, revocation) · VS04 RabbitMQ + Java/Python worker connectivity (envelopes, ack/correlation, heartbeat, duplicate delivery) · VS05 deployment + health (Compose, Render Blueprint, protected env, health/readiness, sanitized correlation logs, smoke tests, recovery docs).
**P1 Identity & Workspaces** — VS01 invitation/activation/recovery · VS02 admin account management · VS03 Workspace creation + Owner (atomic, never Owner-less, transfer, capabilities) · VS04 roster import + membership · VS05 project/team formation (min/max, one active project per Workspace, concurrency) · VS06 dashboards + navigation (capabilities from backend).
**P2 Requirements & Intake** — VS01 versioned Requirements Sets (draft/validate/publish/assign, history, copy-on-apply) · VS02 SDLC workflow designer (DAG, immutable versions, stage progress) · VS03 artifact definitions + DOCX templates · VS04 participant intake + Google Drive (drafts, upload, Drive link import, OAuth, Project > Workspace > Admin default, durable refs, immutable submission) · VS05 validation + corrections (errors/warnings, Blocking/Advisory revisions, deadlines/extensions) · VS06 version history + controlled configuration migration.
**P3 AI Evaluation & Review (MVP complete)** — VS01 rubrics, provider/model registry, qualification, routing, review/approval policies · VS02 eligibility + idempotent initiation (outbox) · VS03 durable execution (RabbitMQ, Java + Python, leases/heartbeats/fencing, bounded retry, distinct-attempt fallback, SSE + REST, recovery/incidents) · VS04 independent review + adjudication · VS05 final approval (one-/multi-approver) + explicit publication · VS06 published feedback, revisions, corrected resubmission, full MVP E2E, release evidence.
**Post-MVP:** code ingestion (GitHub/ZIP) and implementation verification, AI requirements extraction/lineage, document-vs-code conformance, analytics, notification campaigns, advanced backup/retention automation, Agile change-impact, advanced exports/traceability, SSO.

## MVP acceptance scenario (brief section 8 — whole workflow on the real integrated app)
1 admin provisions/activates accounts · 2 Coordinator creates Workspace · 3 Participants imported/enrolled, teams formed · 4 Requirements Sets configured + published · 5 SDLC workflow configured + assigned · 6 artifact obligation + DOCX template defined · 7 Participant downloads template · 8 prepares draft · 9 uploads or imports authorized Drive link · 10 intake-security + structural validation · 11 accepted immutable artifact stored at resolved Drive destination · 12 Coordinator starts eligible AI evaluation · 13 RabbitMQ dispatches durable job · 14 Java + Python workers process with qualified AI · 15 evidence-grounded findings + immutable provenance · 16 reviewers examine/adjudicate · 17 one-/multi-approver requirements satisfied · 18 authorized Coordinator explicitly publishes participant-safe feedback · 19 Participant views published feedback + relevant older versions · 20 Participant submits a corrected version.

## Definition of Done (per slice)
Requirements implemented or dispositioned · frontend works · backend + authorization work · persisted state verified · external integrations work · positive and negative tests pass · critical Playwright E2E passes · release gates pass · no acceptance-blocking issue · git/CI/environment/evidence recorded in `docs/slice-tracker.md`.

Before closing a phase: run die-qa on its slice, die-security-reviewer on auth/file/data changes, and update CLAUDE.md, ADRs and the tracker.
