# DIE — Document–Implementation Evaluator

AI-assisted academic evaluation and governance platform for student SDLC projects. **Not an autonomous grader.** AI output is advisory; authorized human reviewers and approvers decide everything.

## Brief v1.0 supersedes the original brief (2026-10-18)
`docs/brief.md` is the controlled baseline (MVP = P0–P3; old brief kept as `docs/brief-v0-original.md`). Key changes: roles are **Participant / Coordinator / Administrator** (Class = Project Workspace with a single Owner; the public API/UI use Workspace/Participant/Coordinator since ADR 0002 (`docs/decisions/0002-workspace-vocabulary-and-admin-content-access.md`): `/api/v1/workspaces`, roles PARTICIPANT/COORDINATOR/ADMIN, migration V7; internal Java names and DB tables still say class/student/instructor); **Admin has no automatic access to private project documents, reviews or approvals** (enforced structurally: `ProjectRole.ADMIN.canAccessContent()` is false; every content endpoint must gate on `AccessPolicy.requireProjectContent`/`requireClassContent`); **requirements sets are in P2**; Drive precedence is **Project > Workspace > Admin default** (no instructor tier); intake is DOCX (upload + Drive link); P3 has independent multi-reviewer review, adjudication, one-/multi-approver quorum, publication revisions; frontend is part of each slice (Tailwind, shadcn/ui, TanStack Query, RHF+Zod); code analysis is post-MVP. Where this file or `docs/p2-plan.md` conflict with the brief, the brief wins; open points are listed in `docs/brief-reconciliation.md`. **Old paths/values in the P1 sections below (`/classes`, STUDENT, INSTRUCTOR, `studentId`, `classId`, `STUDENT_FORMED`, error codes) were renamed by ADR 0002; the rename was verified on 2026-10-18 (203 tests pass).** The phase list below is the brief v1.0 list.

## Stack (fixed)
- Frontend: React + TypeScript + Vite (Render Static Site). Talks only to the Spring Boot REST API.
- Backend: Java Spring Boot 4.1.1 (Spring Framework 7, Security 7, Jackson 3 `tools.jackson`, Flyway 12, Testcontainers 2), modular (clear domain boundaries), Spring Security, server-side sessions, HttpOnly cookies, CSRF. API base `/api/v1`, OpenAPI published, consistent error shape, SSE for evaluation progress (polling fallback).
- DB: Supabase PostgreSQL **as plain Postgres only** (no Supabase Auth/Storage). Flyway versioned SQL migrations only. Least-privileged app DB user.
- Queue: RabbitMQ (own container; durable queues, persistent msgs, publisher confirms, manual acks, retry + DLQ). Transactional outbox from Postgres to RabbitMQ.
- Workers (separate Docker images): Java orchestration worker; Python document-analysis worker (DOCX/PDF parse, sections, normalization, deterministic validation, evidence location mapping).
- Storage: provider abstraction, Google Drive first (personal, Workspace, Shared Drives); S3-compatible later. Destination precedence: project > workspace > admin default (brief v1.0 C-01).
- Deploy: Render Blueprint; Docker Compose for local dev.

## Code conventions (mandatory — details in `.claude/skills/die-code-conventions`)
- Base package **`com.blissfuljuan.dieapi`**. Every module is layered Model-View-Controller: `<module>/{controller,view,model,service,repository}` (C = controller, V = view = response records, M = model + service + repository). Only `config` and `common` sit outside. `MvcArchitectureTest` (ArchUnit) enforces it, so new modules must follow it too.
- One global error handler (`common.controller.GlobalExceptionHandler`): RFC 9457 body with `code`, readable `detail`, `timestamp`, `traceId` (= `X-Request-Id`), `errors[]` for validation; business failures throw `ApiException` with a specific code; unexpected errors never leak internals; 401/403 from the security filters use the same format.
- **SOLID + design patterns are mandatory** (ADR `docs/decisions/0001-solid-and-design-patterns.md`, skill `die-code-conventions`): strategies/registries for varying behaviour, ports & adapters for infrastructure, enums instead of string roles/statuses, no SQL in services. The migration of existing code (`docs/refactor-plan.md`) is finished; see "Refactor status" below. P2 plan: `docs/p2-plan.md` (reconciled with the brief).
- Older notes below use short, module-relative class names (e.g. `access/AccessPolicy`): the classes now live in `<module>/<layer>/`.

## Non-negotiable invariants
1. AI never finalizes anything. Original AI output is never overwritten; reviewer edits are separate records. AI-suggested scores are visually/structurally distinct from approved scores.
2. A passing AI score never completes a stage; Coordinator-defined conditions + approval do.
3. LLM evaluation runs only when an authorized Coordinator triggers it. Participant submission never triggers it (deterministic validation at intake is fine).
4. Participants see only published, approved content (administrators have no content access either). Enforce in backend authorization and data access, never only in the UI. Publication is separate from approval.
5. No expensive AI/code analysis in request threads; everything goes through outbox -> RabbitMQ -> workers. Jobs idempotent and recoverable; Postgres holds authoritative job state.
6. Every AI finding cites evidence; citations are verified before shown as verified (states: verified / partially supported / not verified / contradicted / not applicable). Invalid citations flagged or excluded. Evidence != proof the code works.
7. Uploaded documents/repos are untrusted data: prompt-injection resistant, no secrets sent to AI providers, never execute participant code/build scripts, safe archive extraction, malware scan.
8. Versioning is immutable: template, workflow, rubric, submission, model config versions; evaluations pin resolved snapshots (rubric snapshot, template version, input versions).
9. Audit trail for submissions, reviews, approvals, publications, security-sensitive admin changes, requirement changes, finding supersession.
10. Authorization checks combine role + workspace membership + project membership + reviewer/approver assignment + workflow permission + storage-connection ownership.

## P1 slice 6 — roster import (done, 81 tests pass)
`roster/` package. Flow: `POST /api/v1/classes/{id}/roster-imports` (multipart `file`, .csv/.xlsx, 5 MB, 500 rows) -> preview (nothing written except the import + its rows) -> `GET /api/v1/roster-imports/{id}?action=&page=&size=` -> `PUT /roster-imports/{id}/resolutions` -> `POST /roster-imports/{id}/commit` (one transaction; returns one-time temp credentials with `Cache-Control: no-store`) -> `DELETE` cancels a preview. Row outcomes: CREATE, MATCH (existing student, enroll/reinstate), SKIP_DUPLICATE (already enrolled / repeated in file), CONFLICT (kinds: ID_NAME_MISMATCH [USE_EXISTING|SKIP], EMAIL_TAKEN and EMAIL_REPEATED_IN_FILE [CREATE_NEW without email|SKIP], ID_REPEATED_WITH_DIFFERENT_NAME / NOT_A_STUDENT / ACCOUNT_DEACTIVATED [SKIP]), INVALID (reported, never blocks). Unresolved conflicts block commit. Commit re-analyzes the stored rows and returns 409 with nothing written if any outcome changed since the preview. Re-commit is a no-op (`alreadyCommitted`, no credentials). Enrollment rules are shared via `academic/EnrollmentRules` (manual enroll + import). Temp credentials for new accounts are hashed in parallel (`TempCredentialService.issueMany`). `POST /classes/{id}/enrollments/{studentId}/temporary-credential` lets class staff re-issue a lost credential for a never-activated student (response `{secret, expiresAt}`). Import resources are staff-only: outsiders AND enrolled students get the same 404 as for a missing import.
Parser hardening: extension + content sniff (UTF-8 w/o NUL; ZIP magic), no formula evaluation (formula cells -> INVALID), cells starting with `= + @` (or `-` + non-number) -> INVALID, control characters rejected, first sheet only, size/row/column caps, student numbers matched case-insensitively. **Future exports of roster data (CSV/XLSX) must still escape leading `= + - @` characters.** Known limits: no raw file retention (only SHA-256); 500-row cap (Argon2 cost per new account); case-insensitive student-number uniqueness is enforced in the importer but the DB unique index is still case-sensitive (reviewer LOW item, open).
V5 migration adds `roster_import_row.conflict_kind` (+ check) and `roster_import.committed_by`.

## P1 slice 7 — projects & teams (done, 95 tests pass)
`project/` package; `AccessPolicy` gained `ProjectRole` (NONE/MEMBER/REPRESENTATIVE/STAFF), `requireProjectView/Edit/Staff` and `visibleProjects()`. Rules: classmates who are not on a team and outsiders get the same 404 as for a missing project; plain members get 403 on edits; only staff (admin / instructor of the class) can archive, replace members, read membership history. **Policy decisions:** a student is on at most one ACTIVE project per class (enforced under the class row lock); archived projects release their students; students can only create TEAM projects, only in `STUDENT_FORMED` classes, and become representative; individual projects and assigned teams are created/managed by staff (individual-project members cannot edit it); representative or staff can edit title/description/team name, hand over the representative role, and invite classmates (members + live pending invitations are capped at the class maximum; invitations expire after 7 days, `die.team.invitation-days`); accepting re-checks class policy, enrollment, capacity and one-project-per-class, and cancels the student's other pending invitations; students may leave a team only if the class has `students_may_change_teams` (representative role then passes to the earliest-joined remaining member; an empty team is archived); staff `PUT /projects/{id}/members` enforces min/max unless `allowSizeException`; membership history is append-only (role changes close and reopen rows); `project.version` is bumped by membership changes and PATCH/PUT members require the last-seen version (409 if stale); students never see classmates' student numbers; `GET /classes/{id}/eligible-classmates` lists invitable classmates (names only). ### M2 fixed — roster commit hashing is bounded (123 tests pass)
`RosterImportService.commit` is now three phases: (1) short read-only transaction (authorize, state, count the accounts to create); (2) admission control (`roster/CommitLimiter`: one commit per user at a time, `die.roster.max-concurrent-commits` = 2 per instance, else 429) then `account/CredentialHasher.prepare(n)` hashes on a dedicated bounded pool (`die.credentials.hash-threads` = 4, bounded queue `hash-queue`, `hash-timeout-seconds`; saturation/timeout -> 503) with NO transaction, connection or lock held; (3) one write transaction that locks, re-validates the preview and only inserts the pre-computed hashes (`TempCredentialService.storePrepared`). Refused (429/503) or failed commits change nothing and release their permit. `CredentialHasherTest` (bounded parallelism, queue saturation, timeout), `CommitHashingLimitsIntegrationTest` (no locks held while hashing, per-user and global caps, retry after refusal). Remaining caveat: limits are per API instance (in-memory); for multi-instance production the cap is per instance, which is what protects each instance's own pool. Rule for future bulk work: never hash or call external services inside a transaction that holds row locks.

Every POST/PUT/PATCH/DELETE needs the CSRF token: `GET /api/v1/auth/csrf` sets the `XSRF-TOKEN` cookie and returns the token; send it back as `X-XSRF-TOKEN`. `springdoc.swagger-ui.csrf.enabled=true` makes Swagger UI do that automatically once the cookie exists (call the csrf endpoint first). A missing/wrong token is a **403** (`CsrfOnRealServerTest`, runs on a real Tomcat). Pitfall fixed: container-level `sendError()` responses are re-dispatched to `/error`, which used to be protected, so anonymous callers saw an empty-body 401 instead of the real status; `SecurityConfig` now permits the ERROR dispatch type. MockMvc does not reproduce error dispatches — use a RANDOM_PORT test for status-code questions around the filter chain.
